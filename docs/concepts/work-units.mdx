# Work units

A work unit joins an issue, repository and branch with the sessions performing
work. Its lifecycle (`open`, `committed`, `resolved`, or `abandoned`) is separate
from the issue's lifecycle and from its current responsibility. A unit may have
assignment and executor bindings as well as a responsible user and session;
those bindings do not themselves confer responsibility.

## Responsibility and handoff

Ordinary mutations preserve responsibility. An authorized agent may explicitly
assume it from a live, stopped, archived, or unknown holder, providing a reason
and the observed `custody_generation`. A holder may hand off to a successor, or
relinquish responsibility. These operations advance the generation and preserve
the work and its historical authorship; stale writers are rejected. A transfer
neither stops an existing process nor grants approval for protected effects.
Liveness is informational for responsibility, while process and controller
fences still protect execution.

Umbrella parent roles follow the same principle using an observed role checkpoint.
A merge request follows its delivery work unit's responsibility; an unbound
request has its own responsibility. See [Architecture](/docs/concepts/architecture)
and [Approvals](/docs/features/auth-queue).

## Creating and completing work

A worktree policy tool can register a unit when creating a branch, for example:

```sh
wt new feature/my-feature --issue abc1234
```

The `.issue` file connects subsequent `commit-linked` commits to the issue.
`mandible work-unit find` reports the unit and generation;
`mandible work-unit custody-check` reports responsibility and the appropriate
assumption command when needed. The `claim`, `activate`, `custody-assume`,
`release`, and `resolve` commands expose the underlying operations.

A successful merge resolves associated work units and closes the issues named
as closure targets on the approval request. A positively identified child worker
may become eligible for archive after its assigned units resolve; unknown
liveness defers that cleanup. Reconciliation also detects commits and confirms
branch deletion before abandoning work.
