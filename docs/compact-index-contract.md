# Compact index publication contract

Owned by [issue:673c86b]; consumed by [issue:44569c8]. Physical version is 19. `src/conversations/conversation-index.ts` defines the body-free `IndexWriteBatch` persistence model. Write positions carry structured handoff/response/execution recipes, and fragments carry disclosure recipes. String-rich `PositionFacts` and `FragmentFacts` are derived reader views. Source positions retain the existing SHA-256 revision, encoded as 32 bytes on disk. Complete and bounded readers return canonical facts; hydrated renderer items are projected into the same activity summarization rule.

`ConversationStructureCache` exposes `beginGeneration(manifest, priorVersionId?) → number`, `appendGeneration(id, {rows?, display?, tools?})`, `completeGeneration(id)`, and `discardGeneration(id)`. Begin creates a building generation and optionally copies an exact ready prefix. Append commits bounded batches; complete validates contiguous source positions, position facts and owned references before atomically setting ready. Every nonempty source position requires its revision facts, even when all display fragments are filtered out. A replacement for a malformed ready header builds separately and retires the prior same-tuple publication only in the ready-marker transaction. Reads admit only ready generations. Conversion leaves source ledger pointers untouched. Converter begin is idempotent for an exact ready tuple; normal `replaceRows` explicitly rebuilds its facts with `beginGeneration(..., {replaceReady: true})` because normalized finality or completion evidence can be enriched without changing source-version or position-space identity. The replacement stays private until the ready-marker transaction.

The storage module exports `CONVERSATION_CACHE_FORMAT` with version, table ownership and schema SQL, and `projectConversationCache(sourcePath, destinationPath, manifests)` selecting exact ready tuples. Generation-copy and projection use the same ownership inventory. Copies use bounded keyset scans, admit ready tuples only and skip unavailable cold tuples. `maxBytes`, `signal`, `batchSize` and `cooperate` options apply shared preview limits. The constructor accepts `maxBytes`, and `setByteLimit(maxBytes)` applies the same SQLite page limit to conversion. No preview-specific table inventory is required.

`legacyDisplayIndexBatch(input, conversationId)` converts a bounded batch of parsed v18 position/fragment facts and aliases into canonical facts. This is a conversion-only projection function, not an old-format runtime read backend. Native identity and disclosure strings are decomposed losslessly into typed recipe rows; source and generation scope are referenced rather than repeated. Tool operations store category/count/native names only when they differ from shared derivation using the already-stored native tool metadata and execution facts; labels/icons are reconstructed by shared presentation definitions. Execution stores kind and ordered shell/forwarding facts, never command input or script bodies. Semantic text flags fit one integer bitset.
