# System API

Health checks, daemon logs, SSE event streaming, backup management, and administrative operations.

## Health

### GET /api/health

Health check endpoint.

**Response:** `200 OK`

```json
{
  "status": "ok",
  "uptime": 3600.5,
  "version": "1.0.0",
  "commit": {
    "hash": "abc1234",
    "summary": "feat: add widget",
    "date": "2025-03-20"
  },
  "sse_clients": 2
}
```

The real daemon also includes a `memory` object with byte counts matching
Node's `process.memoryUsage()` (`rss`, `heapUsed`, `heapTotal`, `external`, and
`arrayBuffers`), process `uptime`, machine `totalMemory`, `rssFraction`, the
configured warning threshold and state, and process-lifetime `highWater` byte
counts. Sampling retains only the current high-water values; it does not retain
a time series.

By default Mandible logs `daemon_memory_warning` when RSS reaches 10% of
machine memory. Set `MANDIBLE_MEMORY_WARNING_FRACTION` to a fraction in `(0, 1]`
for a different threshold (for example, `0.15` for 15%). A recovery event is
logged below 90% of the configured threshold, providing hysteresis so health
polls do not spam the log around the boundary.

The response also includes an `eventLoop` object with p50, p95, maximum, and
process-lifetime high-water delay measurements in milliseconds. Its `warning`
and `backgroundBackoffMs` fields show when background ingestion is pacing work
to protect request responsiveness.

```bash
curl http://localhost:19420/api/health
```

## Server-Sent Events (SSE)

### POST /api/events/subscribe

Subscribe to the SSE event stream. Long-lived connection. Heartbeat comments are sent every 15 seconds to keep the connection alive.

This is the only browser event transport. It requires an authenticated session
and uses the same-origin fetch client so the request carries its HttpOnly cookie
and session-bound CSRF value. There is no anonymous GET or `EventSource`
fallback.

**JSON body or query params:**

| Param | Type | Description |
|---|---|---|
| `topic` | string | Topic prefix filter (e.g., `auth:` for auth events only). Multiple topics separated by commas. |

**Event format:**

```
data: {"type":"auth:resolved","data":{"request_id":"...","status":"completed"},"timestamp":"2025-03-20T10:30:00Z"}
```

**Event types:**

| Type | Description |
|---|---|
| `auth:resolved` | Auth request reached terminal state |
| `conversation:updated` | Conversation metadata changed |
| `daemon:reloaded` | Daemon restarted (includes recent auth results) |
| `mandible:rebuilding` | Daemon is about to restart for a rebuild |
| `mandible:rebuild-failed` | The merge landed, but Mandible did not update; carries the message |

```bash
curl -N -X POST https://app.mandible.localhost:19420/api/events/subscribe \
  -H "Authorization: Bearer $MANDIBLE_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"topics":["auth:"]}'
```

## Logs

### GET /api/system/logs

Query the structured `daemon_log` rows, or tail the NDJSON stderr log when no
log database is available.

Each request examines at most the newest 10,000 candidate rows before `before`.
The candidates come from the first keyed filter (`related`, then `event`, then
`subsystem`) within `since` and `until`. Other filters and the facets apply
inside that window. When the window is full, `older_cursor` continues from its
boundary, so a page can be short or empty while `has_older` is true.

**Query params:**

| Param | Type | Description |
|---|---|---|
| `levels` | string | Comma-separated levels: `debug`, `info`, `warn`, `error` |
| `level` | string | Minimum level when `levels` is absent (default: `info`) |
| `subsystem`, `event` | string | Exact match |
| `q` | string | Substring match over event, subsystem, fields, and entity ids |
| `related` | string | Entity id, optionally typed: `issue:`, `auth:`, `artifact:`, `session:`, `repo:` |
| `since`, `until` | string | Timestamp bounds (ISO or epoch milliseconds) |
| `before` | string | `older_cursor` from a previous response |
| `limit` | number | Max entries (default: 200, max: 1000) |
| `offset` | number | Skip the newest N matches (default: 0) |

**Response:** `200 OK`

```json
{
  "entries": [{ "id": "…", "level": "info", "event": "http_request", "subsystem": "http", "time": "2026-10-19T10:30:00.000Z" }],
  "limit": 200,
  "offset": 0,
  "log_file": "/Users/user/.cache/mandible/launchd-stderr.log",
  "exists": true,
  "source": "daemon_log",
  "facets": { "subsystems": [], "events": [], "entity_refs": [], "latest_ts": "2026-10-19T10:30:00.000Z" },
  "older_cursor": "…",
  "has_older": true
}
```

```bash
curl "http://localhost:19420/api/system/logs?level=warn&limit=50"
```

## Backup

### GET /api/backup/status

Get backup scheduler status.

**Response:** `200 OK`

```json
{
  "enabled": true,
  "interval_hours": 6,
  "destination": "/Users/user/.mandible/backups/mandible-metadata.sql",
  "last_run_at": 1711234567890,
  "last_size_bytes": 524288,
  "last_error": null
}
```

### POST /api/backup/run

Trigger an immediate in-process metadata backup.

**Response:** `200 OK`

```json
{ "ok": true, "size_bytes": 524288, "path": "/Users/user/.mandible/backups/mandible-metadata.sql", "destination": "/Users/user/.mandible/backups/mandible-metadata.sql" }
```

Or on failure:

```json
{ "ok": false, "error": "EACCES: permission denied, open '...'" }
```

The dump contains Mandible-owned metadata tables and excludes large rebuildable
content such as `conversation_blocks`. Restore is deferred until Mandible has a
tested restore round trip.

### PUT /api/backup/settings

Update backup configuration. Reschedules the backup timer.

**Request body:**

| Field | Type | Description |
|---|---|---|
| `enabled` | boolean | Enable/disable scheduled backups |
| `interval_hours` | number | Hours between backups |
| `destination` | string | Metadata backup output file |

**Response:** `200 OK`

```json
{ "ok": true }
```

```bash
curl -X PUT http://localhost:19420/api/backup/settings \
  -H 'Content-Type: application/json' \
  -d '{"enabled": true, "interval_hours": 12, "destination": "/Users/user/.mandible/backups/mandible-metadata.sql"}'
```

## Administrative

### POST /api/admin/rebuilding

Broadcast a `mandible:rebuilding` SSE event to all connected clients. Called by the post-merge hook before initiating a daemon restart so the UI can show a splash screen.

**Response:** `200 OK`

```json
{ "ok": true }
```

### POST /api/system/open-path

Open a file or directory in Finder (macOS). Path must be under a known repo root (security restriction).

**Request body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | Path to open |

**Response:** `200 OK`

```json
{ "ok": true }
```

**Error responses:**
- `403` — Path not under a known repo root
- `404` — Path not found
