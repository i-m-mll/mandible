# Full-text search cost and coverage

The sidebar's full-text path previously searched every eligible conversation before returning a bounded page. On an isolated read-only snapshot with 15,346 eligible conversations and 25.584 GB of logical sources, `daemon` with limit 50 was still pending after 45 seconds. At that cutoff it had described 13,440 IDs and finished 3,198 source reads. These observations do not establish a completed-query latency or an HTTP response percentile. [issue:2a96e3d]

Two fixed, current-version cohorts showed where work accrued. A 132.58 MB logical-source cohort took 706.4 ms cold and 66.4 ms warm; a 525.79 MB cohort took 2,073.6 ms cold and 690.7 ms warm. The latter materialized 59.144 MB of masked text, while the first matches required inspection of only 924 of 35,791 blocks. Its unchanged warm query reread 14 of 24 sources because the 32 MiB body cache could not retain the working set. Both cohorts returned identical cold and warm result digests. The detailed instrumented receipt is [artifact-version:47cbe520c9d2].

Coverage is an independent correctness condition. Of 15,373 source records, 12,296 used old or legacy parser or normalization epochs. Only two of those retained any legacy bodies, so a search that skipped unreadable old-epoch sources could report false negatives. The shared readiness classifier and ingestion repair scheduling make native old projections eligible for rebuilding even when file mtime is unchanged. Supported managed durable structures and genuinely empty native structures are classified through the same rule. Search still verifies physical source bytes before claiming a match or no-match. [issue:80c48e6]

The search design uses one verified source reader to scan masked blocks until the first exact match, with successful verified exhaustion required for a no-match. The existing masked-body and physical caches remain bounded; no second corpus-sized body index is introduced. An asynchronous job returns a pending response before corpus preparation, then publishes exact totals and pages only after coverage is complete. Incomplete, superseded and expired jobs carry explicit terminal states without result fields. Completed pages retain the pinned logical snapshot: they check recorded source and rule generations, and physically verify sources displayed on the page without rereading the corpus. A fresh search captures fresh external changes discovered by ingestion and reconciliation. The client retains and labels its last complete results while a replacement job is pending, then swaps in one complete snapshot. [issue:9eb4988] [issue:68a75f0] [issue:23ac610]

For native sparse sources, a search pins the admitted version, block count and model context. A published append can advance the current version while the search finishes against the old sealed prefix if the reader proves complete contiguous old navigation and unchanged old bytes. Changed source generations are rechecked before completion and on snapshot pages. Rewrites, replacement files, redaction changes and late publication during final verification supersede the old snapshot. Historical dense or managed navigation without equivalent old-context proof fails explicitly; later Codex events can change metadata on an earlier dense block, so current dense metadata cannot stand in for that old context. [issue:9eb4988] [issue:68a75f0]

An isolated preview copy exposed a source-mode ingestion gap: the daemon ran Bun TypeScript, while the default ingestion actor accepted only built JavaScript. The shared actor now resolves its worker in either supported Bun mode. After this correction, a Gemini-only cold negative query repaired and scanned all 297 eligible sources (22.3 MiB logical), returned complete coverage with zero failures, and took 8.4 seconds of command wall time including polling. A fresh unchanged query took 0.5 seconds of command wall time. The browser showed prior rows while pending and replaced them with a verified empty result after completion; clearing the query restored the rows. Before the actor correction, the same preview produced an explicit incomplete state and retained prior rows and selection through navigation. These subset observations do not establish full-corpus completion or an HTTP percentile. [issue:80c48e6] [issue:23ac610]

## Integrated validation

The combined branch passed 92 focused tests across source readiness, ingestion demand, verified scanning, full-text jobs, route behavior, CLI, and UI state. Static checks, backend/channel/UI typechecks, and the build passed. A native-shaped fixture projected 15,346 eligible IDs to 3,905,557 bytes of source pins and 12,798,564 bytes of total retained snapshot metadata, below the 32 MiB cap. This is a scaled fixture measurement, not a full live-corpus memory reading.

The signed source and client integration also passed the complete default suite: 432 test files and 3,070 tests, plus static checks, backend/channel/UI typechecks, and build. Native ingestion completes sparse prefix and tail navigation before verifying that an appended source can replace its retained database payload. A source-loss regression test proves the unverified tail remains available when the native file disappears at that boundary. Contiguous, owned append checkpoints continue bounded parsing while their intermediate projection is incomplete.

On the isolated preview, 20 fresh unchanged Gemini-only queries completed with full 297-source coverage. Actual local HTTP first-pending responses had p95 0.642 ms and maximum 0.869 ms; 72 status responses had p95 17.909 ms and maximum 30.695 ms. The corresponding sidebar route log had p95 18 ms and maximum 31 ms across 79 requests. The preview event-loop diagnostic reported a 25.8 ms high-water stall. These are local socket observations under the bounded Gemini workload, not production or full-corpus latency percentiles.

The full eligible preview query for `daemon` returned HTTP 202 promptly, then HTTP 409 `incomplete` about 14.3 seconds later. It counted 15,347 eligible conversations, zero prepared or scanned, and one `source_unavailable` failure. The first candidate required old-epoch Claude repair, but its native source file is absent on this machine. Thus this snapshot cannot supply a complete cold or warm whole-corpus result; no exact totals or empty result were published. The search keeps the coverage failure explicit rather than silently excluding that conversation.
