# Full-text query snapshots

Full-text list, sidebar and dedicated search requests share one worker-owned job service. Title-only requests remain immediate metadata reads. The shared HTTP response union is `FullTextSearchResponse<T>` in `src/conversations/full-text-search-contract.ts`.

The first request returns HTTP 202 before corpus enumeration or preparation. A pending response carries `search_id`, `observer_token`, phase, monotone progress and `retry_after_ms`. It carries no results, exact totals or cursors. Poll the same route with the same normalized filters plus `search_id` and `observer_token`. `cancel=true` releases that observer. Pending observer leases renew for 30 seconds; they govern disposable work and have no relationship to user access.

HTTP 200 `complete` carries the route result, search/snapshot identity and complete coverage. Completed pages need the search ID and their ordinary cursor/page arguments, without an observer lease. A sidebar cursor binds the search ID, normalized filter signature, group and sort. HTTP 409 `incomplete`, `superseded` or `expired` carries a typed reason and coverage facts, without exact totals or cursors. Refreshing an expired search starts a new snapshot explicitly; clients preserve their prior rows until replacement results arrive.

Equivalent active requests share one job. Omitting `search_id` after completion starts a fresh snapshot; existing-ID requests reuse the completed snapshot. Admission permits one active corpus and eight queued keys. The worker prepares source readiness through the ingestion actor at background priority, then scans at most four source conversations concurrently through the shared verified matcher. Unknown, unreadable or unsupported sources cannot prove a negative. Cancellation stops query demand while any shared ingestion repair can finish independently.

Snapshots retain eligible IDs, source/version generations, first-match structural references and frozen order/group metadata. They retain no transcript bodies. The service retains at most four completed snapshots with a combined 32 MiB metadata budget, expiring after five idle minutes. Admission and metadata exhaustion fail explicitly, without truncating eligible results.

Completion proves all pinned sources once. Pages compare canonical source/version/availability/parser/normalization/redaction facts in batches and physically verify only displayed source IDs. They never repeat the corpus matcher. Dedicated search pages hydrate only their matching blocks through the verified reader to produce real structural metadata and masked snippets; sidebar and list pages read no block bodies. Display-only metadata can be hydrated live while page membership/order/grouping stays frozen. A missing row or source identity/availability/epoch/redaction change supersedes the snapshot. Canonical version advances are tracked separately: changed IDs must reprove their admitted sealed prefix before the observed generation is accepted. Native append snapshots retain the admitted block count and normalization model context, with complete bounded prefix navigation; rewritten/replaced prefixes fail explicitly. An external mutation to an undisplayed source that reconciliation has not observed is discovered through ordinary freshness reconciliation or a new query, rather than by reopening the entire corpus on each page.

The parent reader retains only a bounded progress mirror so status requests remain responsive while the worker scans. Worker loss expires its snapshots; an explicit new request can start a replacement worker. Metrics distinguish preparation, projection, scanning, source verification and paging. Source verification includes logical-source decode when required; it does not claim a separately measured decode-only duration. Fast admission is not completed-search latency.
