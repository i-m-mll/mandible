# Installation

Mandible runs locally on your Mac. The currently qualified packaged target is
Apple silicon (arm64) on macOS 15 or later. Linux and Windows packages and an
ordinary public-release updater are follow-up work, not implemented support.

## Install the Mac app

1. Drag the complete `Mandible.app` bundle into `/Applications`.
2. Open Mandible. First launch handles the required local runtime and background
   service setup. Follow any macOS prompts for background-service or local
   certificate permission.
3. Continue into the app. The introduction offers **Choose integrations** and
   **Skip for now**. Either choice lets you keep using Mandible.

The packaged app includes its runtime, commands, and help resources. Running it
requires no source checkout, Bun installation, personal dotfiles, or instruction
compiler. Opening Mandible grants the logged-in OS user access; there is no
login, pairing, or expiring user session. Agent identities and human approval
requirements remain separate from ordinary local access.

## Optional agent connections

**Settings → Agent integrations** shows the exact destinations and current state
of the command-line shortcut, Claude hooks and status line, Claude MCP channel,
and generic Mandible skills for Claude and Codex. Install only the connections
you want. You can copy the command or skill without installing it. Restart the
external agent after changing its integration.

The installed public command is:

```sh
/Applications/Mandible.app/Contents/Resources/bin/mandible help
```

The optional shortcut is `~/.local/bin/mandible`; that directory must be on your
shell's `PATH`. Registrations store the installed app's path. If you move the
app, review the displayed destinations and refresh or explicitly reconfigure
the affected registrations.

**Settings → Instruction Delivery** controls explicit destinations for the
generated command reference. With no configured destinations, Mandible edits no
instruction files. Existing destination lists, modes, and post-export commands
are preserved. Managed blocks preserve surrounding user text. Symlinks and
edited standalone files produce ownership conflicts instead of being replaced.
Your personal skills, roles, worktree conventions, signing policy, and other
instructions remain yours.

Skipping or completing the optional setup persists across refreshes and app
restarts. These controls remain available in Settings. An optional integration
refresh failure is reported separately from required runtime activation.

## Local data

Durable data and configuration, including the ledger, authority, and preferences,
live under `~/.mandible`. Disposable runtime and preview caches live under
`~/.cache/mandible`. Replacing the app does not reset that data. The app's
immutable program files stay inside `Mandible.app`.

The desktop and local browser use `https://app.mandible.localhost:19420`. The
daemon's private loopback backend defaults to `127.0.0.1:29420`. See
[local browser access](../guides/local-browser-sessions.mdx).

## Development from source

These commands are for developing Mandible, not installing the packaged app.
Use Git, the exact Bun revision selected by `scripts/bun-runtime.sh`, and the
platform toolchains required to build native components. Frozen installs use
`bun.lock`; SQLite uses the qualified native library through `src/sqlite.ts`.
See the [Bun runtime contract](../bun-foundation.md).

```sh
git clone <repo-url> mandible
cd mandible
runtime="$(scripts/bun-runtime.sh)"
export PATH="$(dirname "$runtime"):$PATH"
"$runtime" install --frozen-lockfile
"$runtime" run build
"$runtime" run test
```

`bun run dev` watches daemon TypeScript and UI sources. To create or reuse an
isolated browser preview, run `bun run iab-preview -- --json`. Source and preview
instances do not install global agent connections through Settings. The
preview's instruction-delivery changes stay in its copied database and do not
edit target files or run post-export commands.

`bun run tauri:build -- --bundles app` assembles and finalizes the Mac app.
Production qualification uses [exact-candidate acceptance](../candidate-acceptance.md);
a development build or preview does not substitute for that gate. Existing
developer installations migrate through the guarded
[runtime handoff](../runtime-handoff.md), not by opening a second app against
their live writer.
