# Desktop App

Mandible ships as a Tauri 2 native application. The desktop shell opens the web dashboard in a native macOS window and controls the same per-user launchd services used by local runtime operations.

## Architecture

The desktop app has two components:

1. **Tauri shell** (Rust) — a thin native wrapper with a transparent title bar. It connects through the registered HTTPS production origin and installs opaque HttpOnly sessions directly into the webview.

2. **Local services** — launchd owns the Mandible backend and shared HTTPS gateway. The backend's login behavior follows the saved launch mode; configured services restart if their process exits.

## Daemon lifecycle

The desktop checks the backend at `http://127.0.0.1:29420/api/health` and the trusted dashboard at `https://app.mandible.localhost:19420/api/health`. It opens the dashboard only when both report the expected production instance and build and the HTTPS certificate is trusted. Backend health and dashboard availability remain separate status facts.

The behavior depends on the **launch mode** setting:

| Mode | Behavior |
|------|----------|
| **on_demand** (default) | The backend LaunchAgent starts at login. If the backend is stopped while opening the app, Mandible starts it and waits for readiness. |
| **manual** | The backend LaunchAgent does not start at login. The bootstrap screen offers a Start button. |

The launch mode is stored in `~/Library/Application Support/bio.mll.mandible/desktop.json` and can be changed from Settings > Mandible Daemon.

### Health states

The daemon status indicator in Settings shows one of:

| State | Meaning |
|-------|---------|
| **Running** | The backend and trusted dashboard are ready. |
| **Gateway unavailable** | The backend is healthy, but the HTTPS dashboard cannot be reached or verified. The error identifies the gateway issue. |
| **Starting** | An owned service is starting but has not reported ready. |
| **Stopped** | The production backend is not ready. |
| **Port conflict** | A required port is held by an unrecognized process. Mandible preserves that process. |

### Controls

From Settings > Mandible Daemon:

- **Start** — load the backend service and wait for readiness.
- **Restart** — restart the owned backend, then return to the dashboard when navigation finishes.
- **Stop** — stop the production backend. The shared HTTPS gateway remains available when previews use it.
- **View logs** — navigate to the Logs tab.

## Building the desktop app

```bash
# Prerequisites: Rust toolchain, Tauri CLI
npm install
npm run build
cd src-tauri
cargo tauri build
```

The build produces a `.app` bundle and `.dmg` in `src-tauri/target/release/bundle/`. The app is ad-hoc signed (no Apple Developer certificate required for personal use).

## Window configuration

The app opens at 1400x900 with a transparent title bar (macOS-native traffic lights, no title text). The background color is set to `#0b0f14` to match the dashboard theme and prevent a white flash during startup.
