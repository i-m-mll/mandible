# Local browser access

Mandible belongs to the logged-in OS account. A browser at the registered local HTTPS origin resolves the configured human operator on every request. Opening the app, returning after inactivity, refreshing, or restarting the daemon never requires pairing, login, renewal, or a browser session cookie. The browser holds only a same-origin CSRF value for writes. An unmarked human CLI at that origin uses the same identity and obtains CSRF before writes. Managed agents and file-RPC clients continue to present explicit bearer or capability credentials and retain their separate identities.

## Secure local origin

1. Run `"$(scripts/bun-runtime.sh)" run local-front-door -- initialize` to establish the installation identity.
2. Start the production daemon on its private loopback backend.
3. Run `"$(scripts/bun-runtime.sh)" run local-front-door -- install` to install the pinned Caddy binary.
4. Set up secure local connections from the desktop **Connections** action or `"$(scripts/bun-runtime.sh)" scripts/local-ca-trust.mjs setup`. This establishes a per-user trusted certificate root with an explicit macOS trust decision. It is a connection setup action, not a browser login.
5. Start the ordinary front door with `"$(scripts/bun-runtime.sh)" run local-front-door -- run` and open `https://app.mandible.localhost:19420`.

The gateway and daemon require the exact registered host and origin for browser writes. Cross-site requests fail. Browsers cannot send bearer credentials through this route. Protected branch approval, agent attribution, host and origin checks, and preview effects remain separate controls.

## Preview isolation

Each preview has a distinct registered HTTPS hostname, a copied ledger, a private loopback backend, and its own generation, effect ceiling, and writable roots. The front door asks production to sign a five-second context for each preview request. The context is scoped to that preview and its generation; it is a transport proof, not a human access session. The gateway strips cookies and bearer credentials before forwarding. Direct preview requests have no local human identity.

The standard preview allows reads, writes to its copied ledger, and files beneath its registered preview root. Protected auth, production and shared files, external processes, provider sends, network publication, background delivery, and shared maintenance fail closed.

## Connection failure

If the local service is unavailable, the UI keeps its existing content and reports a connection error. Reads wait for a successful retry. A write is never replayed after an uncertain response. Once the service is available, the same OS account can continue without any enrollment or recovery step.
