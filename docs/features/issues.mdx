# Issue Tracking

The Issues tab is Mandible's interface to its local issue ledger. Issues are stored in Mandible's SQLite database, linked to registered repositories, sessions, work units, and auth requests.

## Layout

The view is split into a resizable sidebar (issue list) and a detail panel.

### Sidebar

- **Search filter** — free-text search across issue titles and IDs.
- **Repo filter** — autocomplete dropdown to narrow to a single repository. Mandible scans all repos registered in your `repos.toml` and any repo that has had a session.
- **Status pills** — toggle between All, Open, and Closed. A closed issue carries one canonical resolution: `delivered`, `duplicate`, or `wontfix`.
- **Typed filters** — filter by canonical kind (`bug`, `feature`, `umbrella`, `maintenance`, `experiment`, `tracker`, or `unknown`) and priority (`low`, `normal`, `high`, or `urgent`; new issues default to `normal`). These fields are independent from labels.
- **Labels** — display and filter free-form labels exactly as stored. Labels never stand in for kind, priority, status, resolution, parentage, or branch metadata.
- **Children** — when an issue has outgoing `parent_child` relationships, the "Show children" button narrows the list to those actual child edges. The affordance is based on relationships, not on the issue kind or a label.

Issues are sorted newest-first.

### Detail panel

Selecting an issue shows:

- **Title** (rendered as inline Markdown), canonical status/resolution pill, typed metadata, and free-form label pills.
- **Work unit status** — if the issue has an assigned work unit, this line shows the branch, assignment state (committed/assigned), and agent liveness (active, idle, or unassigned).
- **Action buttons**:
  - *Open in Console* — if an SDK session is actively working on this issue.
  - *Resume Work* — if a continuation (handoff note) exists but no agent is running. Spawns a new SDK session from the Console.
  - *Start Agent* — if no session or continuation exists. Also spawns an SDK session.
- **Description** — the issue body, rendered as Markdown.
- **Activity timeline** — a chronological feed of comments, session starts, auth request submissions, and handoff notes, all interleaved by timestamp.
- **Related entities** — linked sessions, auth requests, and conversations shown as clickable pills that navigate to their respective tabs.
- **Close/Reopen** and **Add Comment** buttons at the bottom.

## Deep linking

Other tabs (Monitor, Inbox, Graph) link to issues via `EntityPill` components. Clicking a pill navigates to the Issues tab with the correct repo and issue pre-selected. If the issue scanner's cache is cold, Mandible triggers a rescan automatically.

## CLI

Issues can also be managed from the command line:

```bash
mandible issue new -t 'Title' -m 'Body' --kind feature
mandible issue list --status open
mandible issue show <id>
mandible issue description show <id>
mandible issue description history <id>
mandible issue comment show issue-ref#last
mandible issue comment history issue-ref#comment-ordinal
mandible issue close <id> --resolution delivered|duplicate|wontfix [--commit <sha>]
mandible issue comment add <id> -m 'Comment'
```

See the CLI reference for the full command set.

## Upgrading older issue metadata

Schema 183 applies general rules such as `fixed` → `delivered` and converts
unambiguous metadata labels into structured fields. It contains no decisions
about particular issues and does not fetch review artifacts during startup.
Already-upgraded databases retain their issue data and migration history unchanged.

An older database with missing closure reasons, conflicting kinds, unresolved
parent references, or inconsistent branch/worker metadata stops with
`v183_metadata_requires_explicit_review`. Back up that database and reconcile
the affected records using the older version's supported issue commands before
retrying the upgrade. Do not invent a closure reason or alter the schema-version
marker to bypass review. One-time review evidence belongs in Mandible custody
and issue history, not application source.
