# Knowledge Graph

The Graph tab shows the same underlying Mandible work ledger through different
perspectives. A perspective is not a filter: it changes the question the graph is
answering, the default node families, and the layout policy used to make the
relationships readable.

## Perspectives

| Perspective | Summary |
|-------------|---------|
| **Activity** | What changed recently or needs attention now. |
| **Issues** | How issues relate to other issues. |
| **Work** | How work moves through repos, branches, sessions, issues, and auth. |
| **Provider Lineage** | What a provider or tool produced from the request and spec to outputs. |
| **Artifact Lineage** | Where an artifact came from and what reused or derived from it. |
| **Provenance** | Evidence for which session, action, commit, or run produced or justified an object. |

The API returns these summaries in each `GraphModeDescriptor`, with
`kind: "perspective"` so clients can label the selector accurately.

## Controls

- **Perspective buttons** choose the graph question and default structure.
- **Layer chips** show or hide node families within the selected perspective.
- **Repo and branch filters** narrow the source data before the graph is built.
- **Time range** narrows recent operational data such as sessions and auth
  requests.
- **Status** chooses open-only or all issue data where the perspective supports
  issue status.
- **Graph size** caps the displayed node count. Connected nodes are preferred
  over isolated nodes so the visible graph keeps useful relationships.

## API

```
GET /api/graph?mode=work&since=3d&repo=mandible&branch=feature/foo&status=open&limit=120
```

Returns a `GraphPayload` with:

- `modes`: perspective descriptors, counts, availability, and summaries.
- `layers`: node-family controls for the selected perspective.
- `filters`: available repo and branch values.
- `nodes` and `edges`: the graph projection.
- `displayed_count`, `available_count`, `limit`, and `truncated`: graph-size
  metadata for the display summary.

Issue and work perspectives are assembled from ledger and operational state.
Provider lineage, artifact lineage, and provenance perspectives use the indexed
provider/artifact graph records.
