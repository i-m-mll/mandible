# Knowledge Graph

The Graph tab renders a force-directed network diagram of your recent activity. Nodes represent sessions, issues, and auth requests; edges represent the relationships between them (parent/child sessions, session-to-issue links, auth-request-to-issue references via `Bug:` trailers).

## Node types

| Type | Shape | Color |
|------|-------|-------|
| **Session** | Small circle | Green if active, grey if ended |
| **Issue** | Larger circle | Purple for umbrella, red for bug, blue for feature, grey for deferred, white for unlabeled |
| **Auth request** | Medium circle | Yellow if pending, green if completed, red if failed/rejected |

## Edges

- **session_parent** — connects a subagent session to its parent.
- **session_issue** — connects a session to the issue it worked on (from the `session_issues` table).
- **auth_issue** — connects an auth request to issues referenced in its `Bug:` commit message trailers.

## Toolbar

The toolbar at the top provides several filters:

- **Repo combobox** — narrow to a single repository. The dropdown is populated from node data.
- **Branch combobox** — further narrow to a specific branch within the selected repo. Disabled until a repo is selected.
- **Time range** — toggle buttons for 1d, 3d, 7d, or all. Controls the `since` parameter sent to the API.
- **Status filter** — "open only" hides ended sessions and closed issues; "all" shows everything in the time range.

Repo and branch filters are applied server-side (the API query); the status filter is applied client-side after data loads.

## Interaction

- **Hover** a node to see a tooltip with its label, type, status, and creation time.
- **Click** a node to navigate to the corresponding tab (Monitor for sessions, Issues for issues, Auth for auth requests).
- **Drag** nodes to rearrange the layout. The simulation re-settles after each interaction.
- **Zoom and pan** with scroll wheel and mouse drag on the canvas background.

## API

```
GET /api/graph?since=3d&repo=mandible&branch=feature/foo&status=open&limit=50
```

Returns `{ nodes: [...], edges: [...] }`. The server assembles nodes from sessions, issues, and auth requests, then computes edges from their relationships. Results are capped at `limit` (default 50, max 500).
